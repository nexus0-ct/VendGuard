# Аналіз обміну VendGuard

I²C bring-up записано з реально запущеної HAL-прошивки у Wokwi. Оригінали знаходяться в Lab02/Work/captures; docs/captures містить фрагменти із SHA-256 та часовим зміщенням у VCD header. Зміст сигналів не генерується скриптами. crop_vcd.py лише зберігає переходи обраного інтервалу.

Часова роздільність Wokwi VCD 1 нс. sigrok використовує downsample=50, 20 МГц. D0=SCL, D1=SDA, D2=UART_TX, D3=PIR, D4=ADC_SAMPLE, D5=UART_RX. Запис починається зі стартом симулятора, без окремого тригера; bufferSize=10000000. Для фізичного аналізатора START на SDA при SCL=HIGH є природною умовою trigger.

## I²C

Перше звернення до WHO_AM_I: START; address 0x68 write; регістр 0x75; slave ACK; STOP; новий START; 0x68 read; data 0x68; master NACK; STOP. Адресний byte 11010000 =0xD0, R/W=0; регістр 01110101 =0x75; read address 11010001 =0xD1. Дев’ятий низький біт означає ACK. Завершальний NACK читання є нормальною дією master.

Адаптер атомарно задає CR2, використовує AUTOEND та STOP між pointer і read. Пауза 120 мкс перед TXDR перевищує 9 тактів по 10 мкс із запасом 30 мкс; RX читається за RXNE без штучних пауз. STM32 HAL виконує початкове налаштування, vendor sources не змінюються.

Запис показує SCL 100 кГц. Перше шестибайтне читання має bytes 00 00 00 00 40 00, тобто 0, 0, 1000 mg. Модуль у спокої 1g, модельна похибка для цього положення 0%. Тестовий вектор та provenance наведено у tests/fixtures/captured-rest.md.

Два записи попереднього bring-up показали аномалії HAL: незавершене memory read після ACK pointer та зайве address 0x00/NACK при переході до read через часткові зміни CR2. Після заміни transfer adapter отримано правильний ID і burst. Це спостереження моделі Wokwi, без перенесення висновку на фізичний STM32.

## Відтворення

Зібрати firmware, запустити Wokwi, дочекатися BACKGROUND_READY і LIGHT_READY. probe читає ID/6 bytes. mpu 69 створює відсутню адресу, mpu 68 повертає робоче опитування. Stop зберігає wokwi.vcd; зберегти оригінал перед наступним запуском.

Відкрити VCD у PulseView з downsample=50. I²C decoder: scl=SCL, sda=SDA; UART: RX=UART_TX, baudrate=115200, 8N1. Текстові анотації формує sigrok-cli. analyze_signals.py незалежно декодує переходи й вимірює час, не стискаючи пауз.

## UART, GPIO та ADC

`recovery-full.vcd`: BOOT починається на 0,103485925 с, MPU CHECK на 0,109603300 с. `uart-boot.sr` показує 56 47 20 (ASCII «VG »), 115200 8N1, молодший біт першим. I²C має 100000 Гц. Медіана періоду ADC за повною записаною серією 20,003075 мс; ширина маркера 71,175 мкс. У adc-schedule перший інтервал 19,5687 мс, отже розклад не є жорстким реальним часом.

PIR у recovery-full: фронт 40,307527050 с, ширина 1000,000025 мс. Перший байт CUSTOMER_DETECTED на 40,309738775 с, затримка 2,211725 мс. Курсори на скриншотах ставляться вручну; точні виміри беруться із переходів VCD. GPIO-маркер охоплює HAL-виклики ADC та не дорівнює лише апаратному часу перетворення.

## Сценарії та відмова

| Оригінал | Час HAL, ms | Результат |
|---|---|---|
| customer-service-full | 207408 | CUSTOMER_DETECTED, INFO, нуль тривог |
| customer-service-full | 302199 | SERVICE_ACCESS, INFO, нуль тривог |
| mechanical-fault-full | 56656 | Удар у service, IMPACT_ALARM |
| mechanical-fault-full | 105845, 105854, 106262 | guard: PIR INFO, удар ALARM, світлова ALARM |
| recovery-full | 25667 | MPU_FAILED, одна FAULT |
| recovery-full | 40308, 56422 | PIR і світлова ознака працюють при NACK |
| recovery-full | 83384, 84398 | MPU_RECOVERED і нове калібрування |

На 0x69 передається 0xD2; дев’ятий біт HIGH є адресним NACK. START→STOP займає 105 мкс. Після повернення 0x68 повторне калібрування триває близько 1 с. Останній справний вектор залишається у STATUS із `imu=NACK calibrated=0`, а детектор його не отримує як новий вимір.

Початковий LDR 1 lux дає 3938 відліків, 479 lux дає 1024. Стрибок MPU Z 1g→1,8g дає 1799 mg і 638401 mg² відхилення. Утримання впливу не дублює запис. Для нового удару повернути 1g і витримати щонайменше 300 мс спокою. Світло повторно озброюється після зниження відхилення до 300 відліків на 400 мс.

## Файли та походження

`originals.json` містить SHA-256 повних оригіналів у Lab02/Work/captures. Кожен фрагмент .vcd містить SHA-256 оригіналу, begin_ns та end_ns. .sr — рівномірні цифрові вибірки для PulseView; паузи не стискаються. .json — незалежне декодування нашим скриптом, .i2c.txt/.uart.txt — анотації sigrok. Файл .pvs містить налаштування декодера; .sr містить власне дані.

У VCD додано кінцеву часову позначку обраного інтервалу, щоб sigrok застосував останній перехід перед EOF. Нові переходи не створюються. Оригінальні повні VCD залишаються незмінними. Збережений customer-service досяг буфера аналізатора; висновки з нього стосуються лише наявних переходів. Для удару й відновлення зроблено окремі повні записи.

```sh
python3 tools/crop_vcd.py /path/to/recovery-full.vcd /tmp/id.vcd 0.10615 0.10668
sigrok-cli -i /tmp/id.vcd -I vcd:downsample=50:skip=0 -o /tmp/id.sr -O srzip
sigrok-cli -i /tmp/id.sr -P i2c:scl=SCL:sda=SDA
python3 tools/analyze_signals.py /tmp/id.vcd --output /tmp/id.json
```

У PulseView відкрити відповідний .sr, додати I²C (SCL/SDA) або UART (UART_TX, 115200 8N1). Для i2c-id збережено .pvs з автоматичним прив’язуванням. Скриншоти містяться у docs/lab_2/img. Вимірювання є результатами цифрової симуляції, без фізичного аналізатора чи електричного стенда.
