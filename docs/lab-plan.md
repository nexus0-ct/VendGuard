# План ЛР1 і ЛР2 для VendGuard

Власник: Шостак Богдан, ІО-36, №20. ЛР1 перевіряє середовище, ЛР2 додає датчики. Критерії нижче є планом, а не результатами.

## ЛР1

1. Зберегти тему, PRD, терміни, компоненти та [вимоги](requirements.md). Доповнити дослідження офіційними datasheet з конкретними сторінками, живленням, струмом, рівнями сигналів і потрібними регістрами. Це ще не завершено.
2. Перевірити Ubuntu 24.04, Docker без `sudo`, `make`, Git і VS Code. До перенесення у VM прочитати `Study/VM-transfer.md`, порівняти файли й визначити фактичний шлях.
3. Виконати `make build`, перевірити `.elf`, `.hex`, `.bin`. Зберегти лог, версію ARM GCC, архітектуру контейнера та ID образу. Шаблон не має цілей `flash` чи `monitor`: у формі B запуск і UART доступні через Wokwi у VS Code.
4. Порівняти SHA-256 двох чистих збірок на тому самому образі. Dockerfile не фіксує digest базового образу й версії apt-пакетів, тому побайтну однаковість на інших машинах ще не доведено. Для суворої відтворюваності зберегти той самий образ або зафіксувати тулчейн та архітектуру перед підсумковою перевіркою.
5. За вже доступної ліцензії запустити `Wokwi: Start Simulator`. Якщо ліцензії немає, залишити перевірку очікувати дій користувача. Trial не активувати.
6. Показати стартовий UART-рядок, п'ять послідовних `tick` і перемикання LED раз на секунду. Зберегти власні скриншоти й UART-лог, додати pinout та clock configuration з CubeMX. `.ioc` уже є.
7. Підготувати звіт і відео за результатами виконання. Звіт зберігати в `../../Reports/`, фінальний PDF для здачі скопіювати в `docs/report.pdf`. Використовувати власні логи й скриншоти.
8. Зберігати зміни окремими комітами за змістом. Git identity та remote вже налаштовано користувачем. PR створює користувач.

Команди майбутньої перевірки в Ubuntu, зараз не виконані:

```sh
make clean
make build
sha256sum firmware/build/firmware.elf firmware/build/firmware.hex firmware/build/firmware.bin > /tmp/vendguard-build-1.sha256
make clean
make build
sha256sum firmware/build/firmware.elf firmware/build/firmware.hex firmware/build/firmware.bin > /tmp/vendguard-build-2.sha256
diff -u /tmp/vendguard-build-1.sha256 /tmp/vendguard-build-2.sha256
```

## ЛР2

Перед виконанням прочитати наявну `Study/Materials/SP/LR2-metodychka.pdf`. Цей план спирається на уточнення викладача; повний розбір методички ЛР2 ще не виконано.

1. Додати PIR із GPIO, MPU6050 через I²C1 і фоторезистор через ADC. Перед генерацією вибрати вільні GPIO й ADC-пін у `.ioc`. PB8/PB9 уже налаштовані для I²C1; PA2/PA3 зайняті UART, PA5 зайнятий LED. Зараз датчиків у схемі немає.
2. PIR перевірити окремо. Початок імпульсу є `CUSTOMER_DETECTED`, без повторного запису на кожному опитуванні високого рівня. Подія не збільшує кількість тривог. PIR не рахує людей і не підтверджує покупку.
3. Додати HAL-драйвер MPU6050, перевірити ідентифікацію й прискорення. Калібрувати спокій, врахувати гравітацію й виділяти короткі зміни понад фон. Пороги й фільтри визначити дослідом. Удар дає `IMPACT_ALARM`, навіть за одночасного PIR.
4. Увімкнути ADC для AO фоторезистора. Визначити базовий рівень закритого відсіку, напрям зміни, фільтрацію й гістерезис. Стійка світлова ознака дає `SERVICE_OPEN_SUSPECTED` в охороні та `SERVICE_ACCESS` без тривоги під час обслуговування. Відкриття в темряві може лишитися непоміченим.
5. Додати явний вибір охорони/обслуговування для навчального сценарію. Спосіб вводу ще не визначено, авторизацію не реалізовано. LED ЛР1 показує роботу циклу; індикація тривог потребує окремого правила.
6. Написати тести драйверів і класифікації. Перевірити спокій, шум, удар, стабільне світло, коливання порогу, обидва режими, тривалий PIR та помилку датчика. Критерії наведено в [PRD](PRD.md).
7. Перевірити одночасні PIR, удар і світлову ознаку. UART має показати інформаційну подію покупця та обидві тривоги. Перед роботою з датчиками замінити `HAL_Delay(1000)` шаблону плануванням за часом, щоб GPIO, I²C й ADC не блокували один одного.
8. Перевірити сигнали логічним аналізатором Wokwi й зберегти результати. За [документацією C031C6](https://docs.wokwi.com/parts/board-st-nucleo-c031c6) DMA не реалізовано, початковий план на нього не покладається. Підтримка периферії не доводить роботу нашої прошивки.

## Стан на 03.10.2026

Підготовлено документацію й Git-репозиторій. Дві чисті Docker-збірки завершилися успішно, SHA-256 ELF, HEX і BIN збігаються. [Логи та параметри перевірки](build-check.md). Окремий запуск в Ubuntu, UART і LED у Wokwi ще не перевірено. Датчики не реалізовано, звіту та відео ще немає.
