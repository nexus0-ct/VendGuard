# PRD VendGuard

Власник: Шостак Богдан, ІО-36, №20. Нижче наведено вимоги до проєкту й план перевірки.

## Ідея

VendGuard повідомляє про удари по корпусу торгового автомата й світлову ознаку відкриття сервісного відсіку. Покупець може підійти без тривоги. Власник автомата отримує категорію події та час від старту через UART.

Проєкт розробляємо у Wokwi на STM32C031C6 з HAL. Оплату, видачу товару й керування замком не реалізуємо. Збереження журналу після вимкнення не плануємо. Зміна світла є непрямою ознакою відкриття відсіку.

## Функціональні вимоги

1. FR-01: система повинна повідомляти про запуск через UART і показувати роботу циклу LED. Для ЛР1 використовуємо код шаблону.
2. FR-02: система повинна фіксувати початок PIR-сигналу як інформаційну подію `CUSTOMER_DETECTED`. Утриманий високий рівень не створює запис на кожному опитуванні.
3. FR-03: поява покупця без удару чи світлової ознаки не повинна створювати запис у журналі тривог або збільшувати їх кількість.
4. FR-04: система повинна виявляти удар за зміною прискорення MPU6050 понад відкалібрований фон і створювати `IMPACT_ALARM`. Спокій із гравітацією й малий шум не є ударом.
5. FR-05: в охороні система повинна створювати `SERVICE_OPEN_SUSPECTED` за стійкої світлової ознаки відкриття. Коливання біля порогу не повинні створювати потік повторних тривог.
6. FR-06: система повинна мати явні режими охорони й обслуговування. В обслуговуванні світлова ознака дає інформаційну подію `SERVICE_ACCESS`. Правило удару діє в обох режимах. Авторизація оператора ще не визначена.
7. FR-07: кожен запис повинен містити час від старту в мілісекундах, категорію та джерело. Інформаційні події, тривоги й помилки мають різні категорії. Збереження після перезапуску та календарний час не обіцяємо.
8. FR-08: поява покупця не повинна приховувати одночасний удар чи ознаку відкриття. Якщо обидві умови тривоги виконано, фіксуються обидві.
9. FR-09: помилка читання або відсутність MPU6050 повинна давати повідомлення несправності, а не удаваний удар. Інші канали продовжують працювати. Для PIR/ADC без додаткової діагностики не обіцяємо виявлення кожного обриву.

## Датчики й альтернативи

| Компонент | Інтерфейс | Призначення | Розглянута альтернатива |
|---|---|---|---|
| PIR, `wokwi-pir-motion-sensor` | GPIO | FR-02, FR-03, рух у зоні покупця | Ультразвуковий датчик дає відстань, але для цього сценарію достатньо події руху. Фізичну модель PIR не вибрано. |
| MPU6050, `wokwi-mpu6050` | I²C | FR-04, прискорення корпусу | Вібраційний вимикач не дає вимірів для калібрування удару. |
| LDR-модуль, `wokwi-photoresistor-sensor` | ADC через AO | FR-05, світло у відсіку | Контакт дверей краще підтверджує відкриття, але не вимірює світло й не додає ADC. Потенціометр перевіряє ADC, проте не моделює світло. |

Три компоненти дають GPIO, I²C та ADC. UART і LED не заміняють датчики. [Опис компонентів та джерела](hardware-components.md).

## План тестування

| Вимоги | Сценарій | Очікуваний результат |
|---|---|---|
| FR-01 | Збірка, запуск Wokwi | Стартовий рядок, п'ять tick, LED змінює стан раз на секунду. |
| FR-02, FR-03 | Лише Simulate Motion, MPU у спокої, світло стабільне | Одна інформаційна подія на початок імпульсу, нуль нових тривог. |
| FR-02 | Довгий PIR-сигнал, LOW, новий HIGH | Дві події за два початки імпульсу. |
| FR-04 | Спокій із 1g, малий шум, короткий імпульс понад поріг | Спокій і шум без тривоги, імпульс дає IMPACT_ALARM. Повторити для різних осей. |
| FR-05 | Стабільне світло, коливання порогу, стійка зміна в охороні | Перші два сценарії без повторних тривог, стійка зміна дає ознаку відкриття. |
| FR-06 | Світлова зміна в обслуговуванні, потім удар | SERVICE_ACCESS без світлової тривоги, удар дає IMPACT_ALARM. |
| FR-07 | Зіставити входи з UART | Правильні категорії, джерела й час від старту. |
| FR-08 | PIR, удар і світлова зміна одночасно в охороні | Інформаційна подія покупця та обидві тривоги. |
| FR-09 | Від'єднати MPU чи змінити адресу, продовжити PIR/ADC | Несправність без вигаданого удару, інші канали працюють. |

У ЛР2 написати тести класифікації на граничних значеннях і тести HAL-драйверів у симуляції. Перед реалізацією визначити пороги, частоти опитування, затримки й місткість журналу. Числові критерії датчиків зараз ще не встановлено.
