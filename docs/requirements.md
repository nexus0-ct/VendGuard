## Методичка

Форма B вимагає STM32 HAL та C/C++, без Arduino-формату. Мінімум три компоненти з трьома різними інтерфейсами. Камера у формі B не обов'язкова. MPU6050 наведено як рекомендований компонент і приклад, а не як єдиний обов'язковий вибір.

Потрібні build-система, UART, дослідження компонентів, `.ioc`, Git-репозиторій та `docs/PRD.md` з не менш ніж вісьмома функціональними вимогами, датчиками, альтернативами й планом тестування. Крок 6 описує генерацію периферії й перевірку обміну, ще без драйверів сенсорів.

Для здачі потрібен PDF у репозиторії з титульним аркушем, процесом виконання, висновком і джерелами. Методичка вимагає власні скриншоти, посилання на коміти, мінімум п'ять фактичних складнощів із поясненням і відео 2–3 хв з голосовим представленням та симуляцією. Відео розміщують на Google Drive, у звіті дають посилання; у Git його не додають. Таблиця командного внеску для однієї особи не потрібна. Здача через PR у `main`.

## План виконання

У ЛР1 демонструємо збірку, UART і LED, готуємо PRD та опис компонентів. Драйвери й спільну роботу датчиків виконуємо в ЛР2 за уточненням викладача. Для здачі ЛР1 також потрібні PDF-звіт і відео.

VendGuard є власною темою, що допускається методичкою. Погодження саме цієї теми викладачем не підтверджене. Не переносимо прапорці Cortex-M4 з прикладу F411/F446 на шаблон C031C6 із Cortex-M0+.

Git налаштовано користувачем. Зміни зберігаємо окремими комітами за змістом. PR для здачі створює користувач. Trial Wokwi не запускаємо.
